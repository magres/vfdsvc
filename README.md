# vfdsvc — часы на переднем дисплее Android TV приставки

У многих приставок на Amlogic (Tanix, T95 и подобные) на передней панели есть
маленький светодиодный дисплей. На заводской прошивке он показывает время
и иконки; в кастомных сборках — например, **slimBOXtv** или других Android 9/ATV —
драйвера для него нет, и дисплей молчит.

`vfdsvc` возвращает дисплей к жизни: маленький демон ставится на приставку по ADB
с обычного компьютера, стартует при загрузке и показывает **время «12:34»
с мигающим двоеточием**, а также зажигает значки **USB, LAN, Wi-Fi** и индикатор
**«воспроизведение»**.

Не нужна ни перепрошивка, ни ядерный модуль. Требуется только root на прошивке —
на slimBOX и похожих сборках он обычно уже включён.

| Состояние | Детали |
| --- | --- |
| Проверено на железе | Tanix TX92 (Amlogic S912, Android 9, прошивка slimBOXtv) |
| Другие приставки | Часто достаточно своего конфига: готовая таблица драйверов поддерживает контроллеры FD628 / FD620 / TM1618 — см. [docs/porting.md](docs/porting.md) |

## Что делает демон

- показывает часы `HH:MM`, двоеточие мигает раз в секунду;
- сам берёт **часовой пояс и формат 12/24 часа** из настроек Android и проверяет
  их раз в час (можно зафиксировать вручную в конфиге);
- зажигает иконки состояния (см. таблицу ниже), все датчики настраиваются
  в конфиге;
- регулирует **яркость** (7 уровней) и **яркость приглушённого режима** отдельно;
- при уводе приставки в спящий режим — приглушает, гасит или не трогает
  дисплей (настраивается).

| Иконка | Когда горит |
| --- | --- |
| 🔇 alarm (будильник) | в системе запланирован ближайший будильник (Google Clock и т.п.) — проверяется раз в 30 с |
| 🗄 usb | вставлена флешка/диск (съёмный накопитель) |
| ▶ play | идёт воспроизведение: занят видеодекодер **или** активен аудиопоток (музыка) **или** (на иных прошивках) wake-lock «Playback» |
| ⏸ pause | видео поставлено на паузу (декодер жив, звук молчит); у «немого» видео сработает тоже — это ограничение датчика |
| **:** colon | всегда (мигает раз в секунду) |
| 🌐 eth | кабельная сеть поднята |
| ✺ wifi | Wi-Fi-сеть поднята |
| bt (метка BT) | Bluetooth включён — светится только там, где есть физическая метка (на M9 Pro и подобных); у TX92 метки нет, поэтому не загорается |

Слоты можно переназначать: ключ `icon_map=` в конфиге задает, какая иконка
какой точкой светится (см. «Кастомизация» ниже).

## Установка на Windows (на примере Tanix TX92)

1. Скачайте архив с последнего релиза ([Releases](https://github.com/magres/vfdsvc/releases/latest))
   и распакуйте его в любую папку, например `C:\vfdsvc`.
2. Узнайте IP-адрес приставки: на пульте — «Настройки → Wi‑Fi / Сеть», строка
   «IP адрес» (выглядит как `192.168.1.100`). Либо посмотрите адрес приставки
   в списке устройств роутера.
3. Дважды щёлкните `install_windows.bat`. Откроется меню:

   ```
   [1] INSTALL   — установить
   [0] UNINSTALL — откатить всё как было
   [T] TEST      — тест дисплея: на 10 секунд зажигаются все сегменты и иконки
   [Q] EXIT
   ```

   Введите `1` и Enter, затем IP-адрес приставки и ещё раз Enter.
   Скрипт сам подключится, проверит root, сделает резервную копию системного
   файла, установит демона и перезагрузит приставку.
4. Дождитесь загрузки приставки (30–60 секунд) — дисплей покажет часы.
5. Настройки по вкусу: файл `conf\tx92-vfd.conf` — обычный текстовый:

   | ключ | значение |
   | --- | --- |
   | `brightness=7` | яркость, от `1` (тускло) до `7` (максимум) |
   | `standby=dim` | что делать в спящем режиме: `dim` — приглушить, `off` — погасить, `keep` — не менять яркость |
   | `standby_brightness=3` | яркость приглушения (1..7); работает при `standby=dim` |
   | `icons=usb,eth,wifi,play,pause,bt,alarm` | какие иконки отслеживать; лишние можно убрать |

   После правки конфига снова запустите `install_windows.bat` и выберите `1` —
   новая конфигурация применится после перезагрузки.
6. Откат: запустите `install_windows.bat` и выберите `0` (UNINSTALL).
   Скрипт вернёт оригинальный `sys_leds` из резервной копии, удалит
   добавленные файлы и перезагрузит приставку. Дисплей снова будет вести себя
   как до установки (то есть на кастомной прошивке — молчать, как раньше).

Для Linux и macOS в архиве есть `scripts/install.sh`:

```sh
./scripts/install.sh 192.168.88.8            # установить
./scripts/install.sh 192.168.88.8 --test 10  # 10 секунд теста дисплея
./scripts/install.sh 192.168.88.8 --uninstall # откат
```

## Что появляется на приставке

- демон `/system/bin/vfdsvc` и конфиг `/system/etc/vfdsvc.conf`;
- вместо `/system/bin/sys_leds` встаёт скрипт загрузки: он освобождает занятые
  пины и запускает демона; оригинал сохраняется рядом как `sys_leds.orig`;
- прошивку и раздел boot скрипты не трогают. При откате всё меняется задним
  числом на исходное: оригинальные файлы возвращаются, добавленные удаляются.

## Частые вопросы

**Чёрное окно мигнуло и исчезло.**
Через «Пуск» или Win+R откройте `cmd`, затем в окне перейдите в папку
архива: `cd /d C:\путь\к\vfdsvc` и запустите `install_windows.bat` — сообщения
не исчезнут.

**«ERROR: no root access».**
На прошивке выключен root или он называется иначе. Попробуйте в окне cmd:
`tooling\windows\adb.exe root`. Если не помогло — прошивка без root, ставить
vfdsvc некуда.

**«Unable to connect» / «Connection refused».**
Приставка выключена, ПК и приставка в разных сетях, или на приставке не
включена «Отладка по ADB» (для этого нужно меню настроек разработчика).
Адрес вводится точно — повторите его и попробуйте ещё раз.

**На дисплее бессмыслица или не все знаки.**
У вашей приставки другая раскладка пинов. Возьмите готовый конфиг своей модели
или посчитайте пины по [docs/porting.md](docs/porting.md) и пришлите его пулл-
реквестом либо откройте issue — добавим конфиг в проект.

## Кастомизация под свою приставку

`vfdsvc` устроен как «движок» + конфиг: специфика конкретного бокса целиком
живёт в файле конфигурации, код пересобирать не нужно. Вся настройка делается
в `conf/<модель>-vfd.conf` (или в установленном `/system/etc/vfdsvc.conf`):

| Что настраивается | Ключ конфига |
| --- | --- |
| GPIO-пины дисплея (CLK/DAT/STB, банк) | `vfd_gpio_clk` / `vfd_gpio_dat` / `vfd_gpio_stb` |
| Порядок цифр на панели | `vfd_chars` |
| Порядок точек-иконок | `vfd_dot_bits` + `vfd_display_type` (выбирает таблицу символов) |
| Ручная раскладка «иконка → точка» | `icon_map=alarm=0,usb=1,play=2,pause=3,colon=4,eth=5,wifi=6,bt=0` |
| Набор трекаемых иконок | `icons=usb,eth,wifi,play,pause,bt,alarm` |
| Датчики «play» | `play_sources=vdec,pcm,lock`, путь декодера — `vdec_file=` |
| Пауза видео | `pause_mode=vdec_no_pcm` или `off` |
| Будильник | `alarm_method=auto/settings/dumpsys/off`, `alarm_interval=5..3600` |
| Bluetooth | `bt_source=rfkill` (или `off`) |
| Fallback на eth1/wlan1 | `net_fallback=on/off` |
| Яркость / яркость сна | `brightness`, `standby` (`dim/off/keep`), `standby_brightness` |
| Детектор сна | `awake_poll=2` (сек): 1) fb0-blank, 2) опрос `dumpsys power` (на slimBOX wake_lock врёт), 3) wake-lock; `0` = отключить опрос |
| Часы | `tz_offset` (ручное), `time_format` (12/24/auto) |

Отправная точка для нового бокса: готовый конфиг своей модели из базы
[vfd-configurations](https://github.com/arthur-liberman/vfd-configurations) +
блок vfdsvc-опций. Пошаговая инструкция (поиск пинов, проволочная отладка,
частые грабли) — в [docs/porting.md](docs/porting.md).

## Универсальность и ограничения

Что поддерживается:

- дисплеи на контроллерах **FD628 / FD620 / TM1618** (3-проводной обмен по GPIO) —
  это большинство Amlogic-боксов светодиодных «часиков»: TX92, TX3/5/6, T95, H96,
  X96 Max, A95X, Magicsee, Ugoos и соседние;
- статические бинарники **armv7 и arm64**, ядра 3.10–4.9, Android 5–9+;
- конфиг-формат совместим с upstream-коллекцией: почти любой готовый конфиг
  бокса подключается копипастой.

Честные ограничения:

1. **FD650 (I2C) не поддерживается** — другой транспорт; на каких-то X96/X98
   дисплеи именно такие. OLED/LCD-панели (SSD1306, HD44780, SH1106) уходят к
   ядерному linux_openvfd, здесь их нет.
2. **Требуется root** на прошивке (adb root или su) и возможность писать
   `/system`; при SELinux enforcing с жёсткими политиками может не заработать.
3. Датчик видео (`vdec`) — Amlogic-специфика: на Rockchip-боксах исчезает
   «видео»-часть (остаётся `pcm` по звуку и wake-lock); на некоторых
   «неадравистых» сборках нет ни того, ни другого — тогда ▶ должен проснуться
   от wake-lock.
4. Будильник — через команды Android (`settings`/`dumpsys`); на чистых
   Linux-сборках (Armbian) отработает не всё — тому виден conf-форс
   (`tz_offset`, `time_format`).
5. Пины может удерживать другой драйвер ядра; отцепка работает через
   runtime unbind, но экзотический владелец, невидимый в `/sys/kernel/debug/
   pinctrl`, может не отпустить.
6. Панель умеет только 4 цифры + 7 точек: без текста; при выключении/перезагрузке
   бокса дисплей гаснет (демона нет); один дисплей на бокс.

## Как это устроено

Дисплей TX92 и подобных приставок — контроллер семейства **FD628/PT6964**,
он подключён тремя проводами к ножкам GPIO процессора (CLK, DAT, STB).
`vfdsvc` разговаривает с ним по однопроводному протоколу, дёргая ножками прямо
из приложения пользователя (userspace) — без ядерного модуля. Скрипт загрузки
замечает, если эти пины уже занял другой драйвер прошивки (на slimBOX это
контроллер i2c), отвязывает его и запускает демона; при остановке демона пины
возвращаются уступившему драйверу.

## Похожие проекты

- [linux_openvfd](https://github.com/arthur-liberman/linux_openvfd) — то же
  семейство форматов, но ядерный модуль (CoreELEC, LibreELEC, Armbian).
- [vfd-configurations](https://github.com/arthur-liberman/vfd-configurations) —
  открытая база конфигов дисплеев; формат совпадает с `conf/*-vfd.conf` здесь.

## История

- **0.1.3** — починил приглушение во сне: на slimBOX wake_lock не снимает
  `PowerManagerService.Display`, поэтому демон не видел «сна». Уровни детекта:
  fb0-blank → опрос `dumpsys power` (`awake_poll=`) → wake-lock (как раньше).
- **0.1.2** — иконки стали полноценными и настраиваемыми: play по трем датчикам
  (видеодекодер/звук/wake-lock — починил «play» на slimBOX), пауза видео,
  будильник (Google Clock), Bluetooth (для боксов с такой меткой), fallback на
  eth1/wlan1; яркость приглушённого сна настраивается (`standby_brightness`);
  любая раскладка задаётся `icon_map=`; README стал понятным Человеку (CAS);
  install больше не ломается об работающего демона («Text file busy»).
- **0.1.1** — README переписан; в архиве он один, без дубликата.
- **0.1.0** — первый публичный релиз (проверен на Tanix TX92).
