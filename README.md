# vfdsvc — часы на переднем дисплее Android TV приставки

У многих приставок на Amlogic (Tanix, T95 и подобные) на передней панели есть
маленький светодиодный дисплей. На заводской прошивке он показывает время
и иконки; в кастомных сборках — например, **slimBOXtv** или других Android 9/ATV —
драйвера для него нет, и дисплей молчит.

`vfdsvc` возвращает дисплей к жизни: маленький демон ставится на приставку по ADB
с обычного компьютера, стартует при загрузке и показывает **время «12:34»
с мигающим двоеточием**, а также зажигает значки **USB, LAN, Wi-Fi** и индикатор
**«воспроизведение»**.

Не нужна ни перепрошивка, ни ядерный модуль. Требуется только root на прошивке —
на slimBOX и похожих сборках он обычно уже включён.

| Состояние | Детали |
| --- | --- |
| Проверено на железе | Tanix TX92 (Amlogic S912, Android 9, прошивка slimBOXtv) |
| Другие приставки | Часто достаточно своего конфига: готовая таблица драйверов поддерживает контроллеры FD628 / FD620 / TM1618 — см. [docs/porting.md](docs/porting.md) |

## Что делает демон

- показывает часы `HH:MM`, двоеточие мигает раз в секунду;
- сам берёт **часовой пояс и формат 12/24 часа** из настроек Android и проверяет
  их раз в час (можно зафиксировать вручную в конфиге);
- зажигает иконки: **USB** — подключена флешка, **LAN** — поднята сеть eth0,
  **Wi-Fi** — поднята сеть wlan0, **play** — идёт воспроизведение;
- регулирует **яркость** (7 уровней);
- при уводе приставки в спящий режим — гасит дисплей, либо оставляет тусклое
  время, либо не трогает вовсе (настраивается).

## Установка на Windows (на примере Tanix TX92)

1. Скачайте архив с последнего релиза ([Releases](https://github.com/magres/vfdsvc/releases/latest))
   и распакуйте его в любую папку, например `C:\vfdsvc`.
2. Узнайте IP-адрес приставки: на пульте — «Настройки → Wi‑Fi / Сеть», строка
   «IP адрес» (выглядит как `192.168.1.100`). Либо посмотрите адрес приставки
   в списке устройств роутера.
3. Дважды щёлкните `install_windows.bat`. Откроется меню:

   ```
   [1] INSTALL   — установить
   [0] UNINSTALL — откатить всё как было
   [T] TEST      — тест дисплея: на 10 секунд зажигаются все сегменты и иконки
   [Q] EXIT
   ```

   Введите `1` и Enter, затем IP-адрес приставки и ещё раз Enter.
   Скрипт сам подключится, проверит root, сделает резервную копию системного
   файла, установит демона и перезагрузит приставку.
4. Дождитесь загрузки приставки (30–60 секунд) — дисплей покажет часы.
5. Настройки по вкусу: файл `conf\tx92-vfd.conf` — обычный текстовый:

   | ключ | значение |
   | --- | --- |
   | `brightness=7` | яркость, от `1` (тускло) до `7` (максимум) |
   | `standby=dim` | что делать в спящем режиме: `dim` — тусклое время, `off` — погасить, `keep` — не менять яркость |
   | `icons=usb,eth,wifi,play` | какие иконки отслеживать; лишние можно убрать |

   После правки конфига снова запустите `install_windows.bat` и выберите `1` —
   новая конфигурация применится после перезагрузки.
6. Откат: запустите `install_windows.bat` и выберите `0` (UNINSTALL).
   Скрипт вернёт оригинальный `sys_leds` из резервной копии, удалит
   добавленные файлы и перезагрузит приставку. Дисплей снова будет вести себя
   как до установки (то есть на кастомной прошивке — молчать, как раньше).

Для Linux и macOS в архиве есть `scripts/install.sh`:

```sh
./scripts/install.sh 192.168.88.8            # установить
./scripts/install.sh 192.168.88.8 --test 10  # 10 секунд теста дисплея
./scripts/install.sh 192.168.88.8 --uninstall # откат
```

## Что появляется на приставке

- демон `/system/bin/vfdsvc` и конфиг `/system/etc/vfdsvc.conf`;
- вместо `/system/bin/sys_leds` встаёт скрипт загрузки: он освобождает занятые
  пины и запускает демона; оригинал сохраняется рядом как `sys_leds.orig`;
- прошивку и раздел boot скрипты не трогают. При откате всё меняется задним
  числом на исходное: оригинальные файлы возвращаются, добавленные удаляются.

## Частые вопросы

**Чёрное окно мигнуло и исчезло.**
Через «Пуск» или Win+R откройте `cmd`, затем в окне перейдите в папку
архива: `cd /d C:\путь\к\vfdsvc` и запустите `install_windows.bat` — сообщения
не исчезнут.

**«ERROR: no root access».**
На прошивке выключен root или он называется иначе. Попробуйте в окне cmd:
`tooling\windows\adb.exe root`. Если не помогло — прошивка без root, ставить
vfdsvc некуда.

**«Unable to connect» / «Connection refused».**
Приставка выключена, ПК и приставка в разных сетях, или на приставке не
включена «Отладка по ADB» (для этого нужно меню настроек разработчика).
Адрес вводится точно — повторите его и попробуйте ещё раз.

**На дисплее бессмыслица или не все знаки.**
У вашей приставки другая раскладка пинов. Возьмите готовый конфиг своей модели
или посчитайте пины по [docs/porting.md](docs/porting.md) и пришлите его пулл-
реквестом либо откройте issue — добавим конфиг в проект.

## Как это устроено

Дисплей TX92 и подобных приставок — контроллер семейства **FD628/PT6964**,
он подключён тремя проводами к ножкам GPIO процессора (CLK, DAT, STB).
`vfdsvc` разговаривает с ним по однопроводному протоколу, дёргая ножками прямо
из приложения пользователя (userspace) — без ядерного модуля. Скрипт загрузки
замечает, если эти пины уже занял другой драйвер прошивки (на slimBOX это
контроллер i2c), отвязывает его и запускает демона; при остановке демона пины
возвращаются уступившему драйверу.

Часы точны и по поясу, и по формату: часовой пояс демон берёт из настроек
Android и пересчитывает раз в час, 12/24 часа — тоже из настроек; иконки
читаются из `/sys/class/net` и wake-lock'ов. Протокол и таблицы символов
основаны на коде ядерного модуля
[linux_openvfd](https://github.com/arthur-liberman/linux_openvfd); здесь он
переосмыслен как userspace-демон: около 200 строк чистого C, статическая
сборка для armv7 и arm64, внешних зависимостей нет.
